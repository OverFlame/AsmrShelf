# AsmrShelf 需求研究与设计备忘

状态：只读研究。本文不改任何代码，只记录代码理解结论与四项新需求的落地方案。
依据：MediaShelf 提交 `0f9d2b1` 的源码、`PROJECTLOG.md` 1571 行、`README.md`、`BUILD_GUIDE.md` 第 13 至 15 节、`docs/DLsite_可获取数据说明.md`。

原剥离指南只覆盖「把音频能力搬出来」这一条线。本文补的四项需求是产品线新增：

1. 刷新（再次导入同一文件夹，以磁盘实际情况为准）。
2. 批量导入（多个 RJ 文件夹一次进库）。
3. 按 RJ 或 VJ 号自动刮削 DLsite 元数据。
4. 自动导入目录与待导入队列。

## 1. 代码理解备忘

### 1.1 现状快照

| 项 | 实测值 |
| --- | --- |
| 源码规模 | `lib` 75 个 dart 文件，26354 行 |
| 最大文件 | `lib/state/app_state.dart` 3302 行 |
| 测试 | 69 个 `_test.dart`，日志记 603 例（待实测） |
| 数据库版本 | `lib/db/tables.dart:13`，`version = 10` |
| 数据目录 | 应用支持目录下 `AudioShelf/`，`lib/services/data_dir_service.dart:31` |
| 库文件名 | `mediashelf.db`，`lib/services/data_dir_service.dart:23` |
| 依赖 | flutter_soloud 4.1.7、audio_metadata_reader 1.7.1、sqflite 2.4.3、fast_gbk 1.0.0 |
| 平台目录 | android、linux、windows（无 ios、macos、web） |

新应用要同时改目录名与库名。只改其中一个，AsmrShelf 会打开 MediaShelf 的老库。

### 1.2 数据层四个机制

**查询双轨。** 音频查询走 `tracks` 视图（视图定义在 `lib/db/tables.dart:177`，访问走 `lib/db/track_dao.dart:129` 起），多媒体查询走 `media` 表（`lib/db/media_dao.dart:320`）。剥离时音频这条线整条带走。

**库归属只有两个值。** `library IN ('audio', 'media')`，见 `lib/db/tables.dart:21`。ASMR 应用只需要 `audio`。

**升级策略必须反转。** 现版本号不一致就 `dropAll` 加 `createAll`，前面有 `migration_guard` 做备份与确认页。剥离指南要求的是拒绝打开高于 v1 的库。所以阶段三沿用守卫的形状，把最后一步从「重建」改成「拒绝」。`dropAll` 本身的修法照抄：扫 `sqlite_master`，再按 `foreign_key_list` 拓扑排序删除。

**AppState 的难点是跨域隐式信号。** 拆成多个状态对象时，四类信号要有明确归属：

| 信号 | 作用 | 拆分的风险 |
| --- | --- | --- |
| `mediaRevision` | 删除后自增，网格靠它重查 | 漏发导致界面显示已删的行 |
| `thumbEpoch` | 缩略图代数 | 改错会让整屏闪 |
| `browsingLibrary` | 页签决定装填范围 | 只按作品库归属判断会让文件夹层空掉 |
| 两套选择集 | `_selectionMode` 与 `_visualSelectionMode` | 批量操作串台 |

### 1.3 音频链路

```
导入  file_scanner → media_rules → ImportService
      → metadata_service → media 行
查询  TrackDao → tracks 视图 → AppState → TrackItem
播放  PlayerController(flutter_soloud) → player_bar / queue_panel / segment_panel
续播  play_position 每 5 秒落库，续播在 play 之后 seek
选段  引擎排他循环区间，优先级高于单曲循环
字幕  subtitle_service 三级归属 → subtitle_parser → subtitle_page
封面  三级回退，换图必须驱逐解码缓存
桌面  无告警播放路径；Android 走通道 mediashelf/playback
```

## 2. 四项需求与现有代码的对应

| 需求 | 现有支撑 | 缺口 |
| --- | --- | --- |
| 刷新 | `ImportService.importDirectory` 按路径去重，重复导入不重复落库 | 不检测磁盘上已消失的文件；不更新已有行；不重挂字幕 |
| 批量导入 | `importSubdirectoriesAsWorks` 已能批量建作品 | 对音频库直接拒绝，见 `lib/state/app_state.dart:2225` |
| RJ 与 VJ 刮削 | 无 | 全仓无 `rj_code`、无 `workno`、无编号识别 |
| 自动导入 | 无 | 全仓无目录监听、无待导入队列、无扫描根目录设置 |

### 2.1 「以实际情况为准」的定义

刷新要让数据库与磁盘一致，具体是五种情况：

| 磁盘实际情况 | 期望结果 |
| --- | --- |
| 新增了音频文件 | 落库，挂到同一作品 |
| 新增了字幕文件（翻译字幕） | 落成字幕行，并归属到对应音频 |
| 文件消失 | 对应行移出数据库，磁盘不动 |
| 文件改名或移动 | 旧行移除，新行落库；用户数据尽量迁移 |
| 文件名与大小都没变 | 不动这一行，保留用户数据 |

用户数据指：作品标题、作品封面与裁剪、标签、播放进度、播放列表、选段。

### 2.2 现有导入的真实行为（逐条核对过）

| 行为 | 代码位置 |
| --- | --- |
| 先查已有路径，只处理新增 | `lib/services/import_service.dart:81-83` |
| 写库忽略冲突，已存在的行返回 id 0 | `lib/db/media_dao.dart` 的 `insertRowsReturningIds`，默认 `ConflictAlgorithm.ignore` |
| 目录树按物理结构镜像，命中即复用 | `lib/services/import_service.dart:182-220`，`lib/db/folder_dao.dart:285` |
| 作品封面只在缺失时自动设置 | `lib/services/import_service.dart:227` |
| 导入入口总是新建作品 | `lib/state/app_state.dart:1616` |
| 目录内全是已导入文件时直接返回 null | `lib/state/app_state.dart:1611` |

结论：增量「增」这一半已经成立。「删」与「改」完全没有，字幕也不会重挂。

### 2.3 三个必须先解决的结构问题

**问题一：刷新不能复用导入入口。** `importDirectory` 每次都 `_workDao.create(_baseName(dirPath))`，同一文件夹再导入一次会得到第二个同名作品。刷新的正确入口是 `importDirectoryIntoWork(dirPath, workId)`（`lib/state/app_state.dart:1882`），它只加新文件，不建作品。

**问题二：作品与磁盘目录没有绑定列。** `works` 表只有 `id`、`name`、`library`、`cover_path`、`sort_order`、`created_at`（`lib/db/tables.dart:18-26`）。现在只能从 `folder_paths` 与 `folders.work_id` 反推作品根目录，遇到多根目录或用户手工改过文件夹时不可靠。刷新需要一个确定的「这个作品对应哪个目录」。

**问题三：字幕行没有创建者。** 音频导入只把匹配到的第一条字幕路径写成字符串，存在 `media.subtitle_path`（`lib/services/import_service.dart:132-146`，`lib/db/tables.dart:51`）。字幕 `media` 行只有走多媒体导入时才产生（`lib/state/app_state.dart:1704-1716` 按扩展名写 `media_type`）。归属关系只有手动入口：`attachSubtitleToAudio`、`setDefaultSubtitle`（`lib/state/app_state.dart:2032-2054`）。所以「导入后自己弄到翻译字幕」这个场景，现在既不会建行，也不会自动归属。

### 2.4 一个容易踩的副作用

`FolderDao.ensureByPath` 命中已有路径时会改写 `folders.parent` 与 `folders.work_id`（`lib/db/folder_dao.dart:300-317`）。用途是复用目录节点，副作用是同一个物理目录被第二个作品导入时，节点会从第一个作品转走。刷新与批量导入都会频繁走这条路，必须显式处理这个归属变更。

## 3. 设计一：刷新

### 3.1 三种触发场景

| 场景 | 范围 | 入口 |
| --- | --- | --- |
| 单作品刷新 | 一个作品目录 | 作品右键菜单、详情页按钮 |
| 多作品刷新 | 勾选的一批作品 | 作品层批量工具条 |
| 自动导入后刷新 | 待导入列表里勾选的条目 | 待导入对话框 |

### 3.2 算法五步

```
1 扫描      FileScanner.scanDirectoryOffThread(root)  → 磁盘清单
2 求差      取库里该作品的全部行（按 path 前缀区间查询）
3 分类      新增 / 消失 / 修改（大小或时间变了）/ 未变
4 落库      删消失 → 更新修改 → 插入新增 → 字幕重挂
5 收尾      文件夹树对齐 → 封面缺失才补 → 一次 refresh
```

第 2 步用现成的区间查询：`MediaDao.queryByDirs` 走 `path COLLATE NOCASE >= ? AND < ?`（`lib/db/media_dao.dart:332-338`），前缀不会误命中相邻目录。

### 3.3 数据保全矩阵

| 情况 | 行是否保留 | 用户数据 |
| --- | --- | --- |
| 路径未变，大小与时间未变 | 保留，不写 | 全部保留 |
| 路径未变，大小或时间变了 | 保留，更新大小、时间、时长 | 全部保留 |
| 路径消失 | 移出数据库 | 随行删除 |
| 路径改名 | 旧行移出，新行插入 | 默认不迁移，见 3.4 |
| 新增文件 | 插入 | 无 |

### 3.4 改名与移动

改名的判定靠不住。文件系统只给新路径，旧行只有旧路径。可以尝试三种线索：

| 线索 | 可靠性 |
| --- | --- |
| 同目录内文件大小与时长完全一致 | 中，同曲多版本会撞 |
| RJ 号加相对路径 | 高，但只对 `RJxxx/track01.mp3` 这类结构成立 |
| 上次导入时间与文件时间接近 | 低 |

建议：不自动迁移。刷新结果对话框单列「疑似改名」一栏，让用户对每一条决定迁移还是当成新文件。这一条列为待拍板项。

### 3.5 删除策略

默认不碰磁盘文件，只移除数据库行。理由有三条：误判磁盘状态不可逆、网络盘短暂掉线会被当成删除、与现有深度删除的语义一致。

建议加一层保险：消失的文件先进「已失联」状态，同一批里第二次刷新仍失联才真正移除。实现上不必加表，用 `media` 现有的 `file_mtime` 与一个「失联计数」列，或者干脆靠对话框二次确认。

### 3.6 字幕重挂

匹配规则已经在 `FileScanner._matchSubtitles` 里（`lib/services/file_scanner.dart:145-185`），四级优先级：完整文件名、完整文件名加语言后缀、去扩展名、去扩展名加语言后缀。刷新时对每个已有音频行做三件事：

| 步骤 | 动作 |
| --- | --- |
| 1 | 若字幕文件还没有 `media` 行，插入一行，`media_type = 'subtitle'` |
| 2 | 调 `SubtitleService.attachAll`（`lib/services/subtitle_service.dart:253`）建立归属 |
| 3 | 音频没有任何默认字幕时，把优先级最高的那条设为默认（`setDefault`，`:194`） |

用户已经手工指定过默认字幕时，第 3 步跳过。判断依据是 `is_default_subtitle` 已经为 1。

### 3.7 并发

导入闸门是 `AppState._beginImport`（`lib/state/app_state.dart:1913`）加 `ImportService._isImporting`。刷新与导入必须共用这一个闸门，串行执行。批量刷新时逐作品排队，不做并行。

## 4. 设计二：批量导入

### 4.1 交互

```
选择父目录（如 D:\ASMR）
  → 列直接子目录
  → 每个子目录一行：名称、RJ 号、音频数、状态
  → 勾选（默认全选新建项）
  → 确认导入 → 逐条串行执行 → 结果表
```

### 4.2 与现有两个入口的关系

| 入口 | 语义 | 音频库可用 |
| --- | --- | --- |
| `importDirectory` | 一个目录一个作品 | 是 |
| `importDirectoryIntoWork` | 往已有作品加文件 | 是 |
| `importSubdirectoriesAsWorks` | 每个子目录一个作品 | **否**，`lib/state/app_state.dart:2225` 直接拒绝 |
| `importSeries` | 子目录当成同一系列的卷 | 是 |

批量导入要的是第三种语义。需要把第 2225 行的拒绝改成音频库也走「每个子目录一个作品」，或者新写一个音频版本。差别在 `_importVisualWork` 走多媒体链，音频要走 `ImportService`。

### 4.3 队列与状态

| 状态 | 含义 |
| --- | --- |
| 待导入 | 扫描发现，未开始 |
| 导入中 | 正在写库，带进度条 |
| 成功 | 新建作品，记录作品 id |
| 跳过 | 目录内没有可导入文件，或全部已导入 |
| 失败 | 记录原因，不中断后续 | 

一条失败不中断整批。这与 `importSubdirectoriesAsWorks` 的现有行为一致。

### 4.4 批量能力矩阵

现代应用该有的批量操作，逐项核对了现有代码：

| 能力 | 现状 | 需要新建 |
| --- | --- | --- |
| 多选 | 已有，`enterTrackSelectionMode`（`lib/state/app_state.dart:2576`） | 作品层多选要复用 |
| 全选 | 已有，`selectAllTracks`（`:2571`） | 反选、按状态过滤勾选 |
| 批量删除 | 已有，`deleteMediaByIds`（`:811`） | 作品层批量删除作品 |
| 批量打标签 | 已有，`addTagsToTracks`（`:2580`） | 带入导入流程 |
| 批量刷新 | 无 | 新建 |
| 批量刮削 | 无 | 新建，接后台队列 |
| 批量导入 | 部分，音频库被拒 | 改造 |
| 批量确认与取消 | 无 | 待导入对话框要用 |

## 5. 设计三：RJ 与 VJ 自动刮削

### 5.1 号码识别

文件夹名形如 `RJ294126 作品名`，编号在开头。识别规则：

```
匹配  ^(RJ|VJ)\d{6,8}   大小写不敏感，取开头
后备  整个文件夹名里搜一次 (RJ|VJ)\d{6,8}
```

长度取 6 到 8 位，因为 DLsite 同时存在 `RJ294126` 与 `RJ01021542` 两种宽度。

识别只做一次，结果写进作品元数据。失败时作品照常入库，只是没有 DLsite 数据。

### 5.2 刮削时机

| 时机 | 默认 | 说明 |
| --- | --- | --- |
| 导入完成时 | 开 | 有编号就排进队列，不阻塞导入 |
| 刷新发现新作品号 | 开 | 只补缺失的 |
| 手动批量 | 用户触发 | 选一批作品重新拉取 |
| 缓存未过期 | 跳过 | 7 天 |

### 5.3 队列纪律

后台队列，单条串行，间隔 10 秒，遵守 robots 的 Crawl-delay。429 与 503 退避两次，403 不重试。这些数值来自 `docs/DLsite_可获取数据说明.md`，与剥离指南第 6 阶段一致。

100 个作品约 17 分钟。所以队列必须可见：进度条、当前作品号、可暂停、可取消、失败原因可查看。

### 5.4 VJ 号未验证

已实测的样本全是 RJ。VJ 号在 DLsite 上属于另一个作品区，接口路径可能不同。这一条必须在 Windows 上用真实 VJ 目录验证，再决定是否合并到同一条队列。

### 5.5 本地优先

本地标题、本地封面、本地标签都不被远程覆盖。远程值只作为候选，用户勾选才写入。这是剥离指南第 10.4 节定的合并策略，刷新与刮削都要遵守。

## 6. 设计四：自动导入目录与待导入队列

### 6.1 设置项

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `auto_import_roots` | 字符串列表 | 扫描根目录，如 `D:\ASMR` |
| `auto_import_on_start` | 布尔 | 启动后自动扫一遍 |
| `auto_import_ignored` | 字符串列表 | 用户点「忽略」的目录路径 |

复用 `SettingsService` 的 JSON 存储，不需要新表。

### 6.2 扫描语义

只扫根目录下的直接子目录，深度为 1。每个子目录视为一个作品候选。不做递归，因为 `D:\ASMR\RJxxx 名字\` 已经是作品边界，递归会把同一作品内的特典目录也当成作品。

判定候选与库内作品是否同一个，用两条：

| 依据 | 优先级 |
| --- | --- |
| 子目录路径等于某作品的根目录 | 高 |
| RJ 或 VJ 号等于某作品已记录的编号 | 中 |
| 子目录名等于某作品名 | 低，仅提示 |

### 6.3 候选状态

| 状态 | 含义 | 默认勾选 |
| --- | --- | --- |
| 新建 | 库里没有 | 是 |
| 有新增 | 库里已有该作品，但目录里有新文件 | 是，单独一栏 |
| 无变化 | 库里已有且文件一致 | 否 |
| 已忽略 | 用户点过忽略 | 否 |
| 不可读 | 权限或路径问题 | 否，显示原因 |

### 6.4 触发方式

只做轮询，不做常驻监听。理由是跨平台一致、网络盘不支持目录事件、移动端耗电。触发点三个：启动后、用户点「自动导入」、用户点「刷新全部作品」。

用户要的行为正是「每次打开或手动点击的时候扫一遍」，与轮询完全吻合。

### 6.5 队列是否持久化

建议不建表。每次扫描实时计算候选，用户忽略的目录写进设置。理由：候选状态可以从磁盘与数据库重算，存表会漂移，还要处理「库被外部改过」的同步问题。

代价是每次扫描要遍历一遍根目录下的子目录并各扫一次文件。100 个作品约 112 万行代码规模的项目里，这一动作在千级文件量下是秒级。实测数据待补。

### 6.6 确认后的执行

用户勾选确认后，逐条执行：

| 候选状态 | 执行动作 |
| --- | --- |
| 新建 | 走批量导入的单条 |
| 有新增 | 走刷新 |
| 无变化 | 跳过 |

这与前两节的设计是同一套执行层，待导入对话框只负责收集用户意图。

## 12. 新增需求：封面回退链与写盘

需求原意：DLsite 封面下载失败时从本地文件里找。本地图可能叫「xx缩略图」，也可能放在「特典」这类目录里，命名不一定是「封面」。都找不到就取文件树里最靠近根的图片。刮到的封面图要写进该 ASMR 作品的根目录。

### 12.1 现有封面机制实测

| 机制 | 位置 | 现状 |
| --- | --- | --- |
| 磁盘封面白名单 | `lib/services/file_scanner.dart:242-250` | 只认 `cover`、`folder`、`front`、`album`、`albumart`、`artwork`、`jacket` 七个英文名 |
| 白名单副本 | `lib/services/volume_cover_service.dart:74-90` | 同一张表的第二份，注释要求两处同步修改 |
| 特典目录 | `lib/services/file_scanner.dart:68-70` | `{'特典', 'sp', 'bonus'}`，只用于打标签 |
| 作品封面候选 | `lib/state/app_state.dart:1423-1445` | 作品无图片行时递归扫根目录，结果按自然序排，无深度与名字权重 |
| 卷封面四级链 | `lib/services/volume_cover_service.dart:110-160` | 白名单图 → 字典序第一张 → 曲目内嵌 → 系列封面 |
| 导入时自动封面 | `lib/services/import_service.dart:227-249` | 根目录白名单图，否则首音频内嵌封面 |
| 封面落盘位置 | `lib/services/cover_service.dart:14-58` | 应用数据目录 `covers/`，`track_<id>` 与 `work_<id>` |

两条结论：

1. 白名单是纯英文，`封面.jpg`、`缩略图.png`、`表紙.jpg` 一个都认不出。目录名信号完全没参与判断。
2. 全仓没有任何代码往用户媒体目录写文件。写盘调用点只有四类：`covers/` 缓存、`playlist/` 导出、数据库备份、数据目录指针。所以「在作品根目录创建封面文件」是全新行为，需要单独的开关与失败处理。

缓存清理不会误删作品封面：`clearEmbeddedCache` 与 `enforceLimit` 只处理 `track_` 前缀的文件（`lib/services/cover_service.dart:83`、`:115`），`work_` 副本安全。

### 12.2 回退链设计

命中即停，最多六级。

| 级 | 范围 | 依据 | 说明 |
| --- | --- | --- | --- |
| 1 | 作品根目录 | 12.3 的两种形态，或命中中文与日文强词 | 如 `cover.jpg`、`RJ294126_cover.jpg`、`封面.png` |
| 2 | 信号目录 | 目录名含「封面」「缩略图」「表紙」「パッケージ」「ジャケット」「サムネイル」「thumbnail」「特典」 | 取该目录内评分最高的图片 |
| 3 | 作品根目录 | 任意图片 | 名称不认识也先用 |
| 4 | 全树 | 深度升序，再名字评分，再自然序 | 「最靠近根的图片」 |
| 5 | 音频行 | 内嵌封面 | 已有的 `track_` 缓存或重新提取 |
| 6 | 无 | 无候选 | 保留默认占位，界面给手动选图入口 |

第 4 级是需求点名的兜底，实现上就是排序键：`(目录深度, -名字评分, 自然序)`。

### 12.3 白名单的两种形态

写入时用的文件名与识别时认的文件名，同时扩成两种形态。

| 形态 | 例子 | 写入时机 |
| --- | --- | --- |
| 通用名 | `cover.jpg` | 作品没有 RJ 或 VJ 号 |
| 编号名 | `RJ294126_cover.jpg` | 作品有编号，外部工具与本应用都能对上这个作品 |

识别规则五条：

1. 通用形态：基名等于 `cover`，大小写不敏感。
2. 编号形态：基名由编号、分隔符、`cover` 三段组成。编号是 `RJ` 或 `VJ` 加 6 至 8 位数字。分隔符允许下划线、连字符、空格，也允许没有分隔符。
3. 匹配按基名整段对齐，不做包含判断。`my_cover_v2.jpg` 不算白名单形态，但仍按强词拿到 35 分。
4. 原有七个英文名继续有效：`folder`、`front`、`album`、`albumart`、`artwork`、`jacket`。
5. 扩展名仍限 `jpg`、`jpeg`、`png`、`webp`、`bmp`。

编号形态的价值有两个：目录里同时放多个作品的封面时不冲突，用户重命名作品文件夹后文件名仍能指认作品。

### 12.4 评分表

| 信号 | 分值 | 备注 |
| --- | --- | --- |
| 文件名命中白名单形态（`cover`、`<编号>_cover`、`folder`、`front`、`album`、`albumart`、`artwork`、`jacket`） | 40 | 大小写不敏感；编号与作品一致时再 +5 |
| 文件名命中强词（封面、表紙、jacket、package、パッケージ、ジャケット） | 35 | 前缀匹配即可 |
| 文件名命中弱词（缩略图、サムネイル、thumbnail、thumb、main、artwork） | 25 | |
| 文件名就是 RJ 或 VJ 号 | 30 | `RJ294126.jpg` 这类 |
| 所在目录命中强词 | 20 | 见 12.2 第 2 级 |
| 所在目录是特典目录 | 10 | 特典里常有成品封面 |
| 每加深一层目录 | -5 | 实施第 4 级排序 |
| 接近正方形或竖版（宽高比 0.6 至 1.1） | +15 | 封面形态 |
| 长边小于 300 像素 | -20 | 缩略图不够用 |

横版样图（如 DLsite 的 753×424 截图）会被比例分压低，正文封面优先。

### 12.5 尺寸探测不能依赖 image 包

剥离要删 `image` 依赖，所以不能用它读宽高。两条替代路径：

| 方案 | 代价 |
| --- | --- |
| `dart:ui` 的 `instantiateImageCodec` 解码 | 每张图都要完整解码，几十张就卡 |
| 自读文件头 | 只读前 64 KB，JPEG 找 SOF 段，PNG 读 IHDR，WebP 读 VP8X 或 VP8 头 |

建议自读文件头，约 40 行，不给剥离后的依赖表加负担。

### 12.6 写盘规则

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 文件名 | 有编号写 `<编号>_cover.<原扩展名>`，无编号写 `cover.<原扩展名>` | 两种形态都在白名单里；编号名能对外指认作品 |
| 编号来源 | 优先用作品目录名里的编号，目录名没有编号时用作品自身编号 | 目录名是用户对作品的称呼，刮削与写盘保持一致 |
| 已存在同名文件 | 跳过，不覆盖。若 `cover.<原扩展名>` 已被占用而编号名未占用，改用编号名 | 用户自己的封面优先；换名写不覆盖用户文件 |
| 写入方式 | `writeFileAtomic`（`lib/utils/file_io.dart:60`） | 临时文件加重命名，断电不留半张图 |
| 字节校验 | 魔数嗅探 JPEG、PNG、WebP | 接口出错时返回 HTML，不能当成图片写下去 |
| 数据库指向 | `works.cover_path` 指向应用缓存 `work_<id>.<ext>` | 用户移动目录不失联，裁剪与换图都在缓存里做 |
| 写盘失败 | 只用缓存，日志 warn，界面不报错 | 只读盘、权限、网络盘都会失败 |
| 来源限制 | 只写 DLsite 下载的那张 | 本地找到的图属于用户文件，不复制、不改动 |
| 幂等 | 存在任一形态即视为已写 | 刷新与重刮不重复写 |

### 12.7 与刷新、扫描的交互

| 场景 | 行为 |
| --- | --- |
| 刷新扫描 | 封面文件是图片不是音频，不进曲目，不影响「有没有新内容」 |
| 封面候选 | 会出现在 `coverCandidatesUnderWork` 里，下次选手动封面时排最前 |
| 用户删掉封面文件 | 显示不受影响，`works.cover_path` 指向缓存 |
| 目录只读或网络盘 | 跳过写盘，封面仍可用 |
| 用户改的标题与封面 | 不被刮削结果覆盖，遵循第 5.5 节的本地优先 |
